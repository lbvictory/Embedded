# I2C

### I2C1

```c
void I2C1_Init(void)
{
    // 1. 开时钟
    RCC->APB2ENR |= 1 << 3;    // GPIOB
    RCC->APB1ENR |= 1 << 21;   // I2C1
    __DSB();

    // 2. 配置 GPIO：复用开漏 0x0F
    GPIOB->CRL &= ~(0xF << 24);
    GPIOB->CRL |=  (0xF << 24);   // PB6 SCL

    GPIOB->CRL &= ~(0xF << 28);
    GPIOB->CRL |=  (0xF << 28);   // PB7 SDA

    // 3. I2C 软件复位
    I2C1->CR1 |= 1 << 15;
    I2C1->CR1 &= ~(1 << 15);

    // 4. 配置 APB1 频率 = 36MHz
    I2C1->CR2 = 36;

    // 5. 配置 100KHz
    I2C1->CCR = 180;
    I2C1->TRISE = 37;

    // 6. 使能 I2C
    I2C1->CR1 |= 1 << 0;
}
```

### I2C2

```c
void I2C2_Init(void)
{
    // 1. 开时钟
    RCC->APB2ENR |= 1 << 3;    // GPIOB
    RCC->APB1ENR |= 1 << 22;   // I2C2
    __DSB();

    // 2. 配置 GPIO：复用开漏 0x0F
    GPIOB->CRH &= ~(0xF << 8);
    GPIOB->CRH |=  (0xF << 8);    // PB10 SCL

    GPIOB->CRH &= ~(0xF << 12);
    GPIOB->CRH |=  (0xF << 12);   // PB11 SDA

    // 3. I2C 软件复位
    I2C2->CR1 |= 1 << 15;
    I2C2->CR1 &= ~(1 << 15);

    // 4. 配置 APB1 频率 = 36MHz
    I2C2->CR2 = 36;

    // 5. 配置 100KHz
    I2C2->CCR = 180;
    I2C2->TRISE = 37;

    // 6. 使能 I2C
    I2C2->CR1 |= 1 << 0;
}
```

## 一、I2C 基础认识

### 1. 是什么

I2C 是**半双工、同步、串行、总线型** 通信协议

- 两根线通信，可挂载多个设备
- 占用引脚极少，外设标配（OLED、EEPROM、温湿度、陀螺仪）

### 2. 两根核心信号线

1. **SCL**：时钟线，由主机控制节拍
2. **SDA**：数据线，双向收发数据

### 3. 角色划分

- **主机**：STM32，控制时钟、发起通信
- **从机**：OLED/传感器/EEPROM，被动响应
- 一条总线：**1主机 + 多从机**，靠「设备地址」区分

### 4. 电压与电平

- 标准：3.3V / 5V 兼容
- 总线默认**高电平**（依赖上拉电阻）
- 无推挽强拉高，只能**主动拉低**

---

## 二、引脚硬件核心（重中之重）

### 1. 电气特性

I2C 是**线与逻辑**：

- 引脚只能**拉低**，不能主动强行拉高
- 高电平全部靠 **4.7K~10K 上拉电阻**
  👉 所以：**绝对不能用推挽输出**

### 2. STM32 引脚配置【必背】

```
硬件I2C  → 复用开漏输出  0x0F
模拟I2C  → 通用开漏输出  0x07
普通外设(PWM/UART) → 复用推挽 0x0B
```

### 3. F103 硬件I2C 引脚

```
I2C1
SCL → PB6
SDA → PB7

I2C2
SCL → PB10
SDA → PB11
```

### 4. 时钟总线

- I2C1 / I2C2 都挂在 **APB1 低速总线**
- 使能位：
  - I2C1：`RCC->APB1ENR |= 1<<21`
  - I2C2：`RCC->APB1ENR |= 1<<22`
- GPIOB 在 APB2

## 三、I2C 时序铁律

### 核心2条

1. **SCL 高电平期间 → SDA 严禁变化**
   - SCL高 = 采样数据
   - SDA乱动 → 芯片误判为 起始/停止信号
2. **SCL 低电平期间 → 允许 SDA 翻转**
   - SCL低 = 准备数据、切换电平

### 四个基础时序信号

1. **起始信号 Start**
   SCL 高 → SDA 强制拉低 → SCL 拉低，进入传输

2. **停止信号 Stop**
   SCL 低 → SDA 先拉低 → SCL拉高 → SDA 释放变高

3. **应答信号 ACK**
   每发完1字节（8bit）
- 从机拉低SDA：**应答 ACK**
- 从机不拉低：**无应答 NACK**
4. **数据位读写**
- 1bit 占用 1个SCL时钟周期
- 高位先行：**先发高位，后发低位**

## 四、速率标准

```
标准模式：100KHz （最常用，全部设备兼容）
快速模式：400KHz （部分高速传感器）
高速模式：3.4MHz （基本不用）
```

我们工程全部统一：**100K 标准模式**

## 五、地址规则（关键）

1. 每个I2C从机有**唯一7位设备地址**
2. 第8位：读写位
- `0` = 写操作
- `1` = 读操作

例：
设备地址 0x3C

- 写指令：`0x78`
- 读指令：`0x79`

## 六、两种 I2C 实现方式（必须分清）

### 方式1：硬件I2C（片上外设）

- 依靠 STM32 内部 I2C 控制器寄存器
- 配置复杂、时序硬件自动生成
- 占用硬件I2C指定引脚
- 优点：CPU负担小
- 缺点：BUG多、F1系列硬件I2C兼容性差

### 方式2：模拟I2C（软件位操作）

- 任意两个GPIO 都能当 SCL/SDA
- 纯代码延时+电平翻转模拟时序
- 配置简单、超级稳定、无bug
- 项目实战**用的最多**

### 引脚配置区别

```
硬件I2C：复用开漏 0x0F
模拟I2C：通用开漏 0x07
```

## 七、STM32F103 硬件I2C 寄存器极简讲解

只讲你要用的4个关键寄存器

1. **CR1 控制寄存器1**
- `bit0`：I2C 使能开关
- `bit15`：软件复位（初始化必清脏数据）
2. **CR2 控制寄存器2**
- 配置 APB1 总线频率（一般填 36）
3. **CCR 时钟控制寄存器**
- 配置 I2C 波特率（100K 固定值 180）
4. **TRISE 上升时间寄存器**
- 固定配置 37，适配100K

> 你之前的初始化代码，就是靠这四个寄存器搭起来的

## 八、完整通信流程（固定套路）

### 写入流程

1. 发送 起始信号
2. 发送「设备地址+写位」
3. 等待从机 ACK
4. 发送 寄存器/命令地址
5. 等待 ACK
6. 发送 要写入的数据
7. 等待 ACK
8. 发送 停止信号

### 读取流程

1. 起始信号
2. 设备地址+写位 → 指定寄存器
3. ACK
4. 重复起始
5. 设备地址+读位
6. 读取1字节
7. 主机发送 NACK 结束读取
8. 停止信号

---

## 九、常见坑（避坑笔记必写）

1. 忘记**先开时钟**，引脚配置全部无效
2. I2C 引脚误用 0x0B 推挽 → 总线冲突、设备不响应
3. 缺少上拉电阻 → 总线一直低电平
4. SCL高电平时改动SDA → 通信乱码
5. 硬件I2C不做软件复位 → 上电卡死
6. 混淆 I2C1 / I2C2 时钟位、引脚

---

## 十、极简背诵总结

1. I2C 两根线：SCL时钟、SDA双向数据
2. 电气：开漏输出 + 外部上拉，不能推挽
3. 配置：
   - 硬件I2C：0x0F 复用开漏
   - 模拟I2C：0x07 通用开漏
4. 时序铁律：SCL高不变SDA，SCL低可改SDA
5. 通信：高位先行、8bit+1bit应答
6. F103 共2组硬件I2C：I2C1/PB67 、I2C2/PB1011
7. 实战优先：**模拟I2C ＞ 硬件I2C**

## 十一、实战补充

### 1. 时钟延展（Clock Stretching）

- 从机处理数据时会将 SCL **拉低**，让主机等待
- 硬件I2C：`CR1` bit7（NOSTRETCH）= 0（默认允许延展）
- 模拟I2C：释放SCL后必须**检测SCL电平**，直至从机释放，加超时

```c
void I2C_Wait_SCL_High(void) {
    uint32_t timeout = 0xFFFF;
    while(!GPIO_ReadInputDataBit(GPIOx, SCL_PIN))
        if(--timeout == 0) break;
}
```

### 2. 总线死锁恢复（Bus Clear）

- 现象：SDA 一直被拉低，无法发出起始信号
- 恢复步骤：
  1. SCL 改为**推挽输出**
  2. 输出 9 个 SCL 脉冲
  3. 每个脉冲后检测 SDA，若变高则发送 Stop 信号
  4. 仍为低 → 需掉电复位从机

### 3. 硬件I2C 关键状态事件（必查）

**主发送流程事件**：

- `SB`：起始条件发送完成 → 读 SR1，写 DR 清除
- `ADDR`：地址发送完成 → **读 SR1 + 读 SR2** 清除
- `TXE`：发送数据寄存器空 → 写 DR
- `BTF`：字节传输完成 → 等待后再发下一字节或停止

**典型错误**：忘记读 SR2 清除 ADDR，导致卡死。

### 4. 模拟I2C 精确延时（100KHz）

- 周期 10μs → 高电平 5μs，低电平 5μs
- 推荐用 `delay_us(5)` 或 SysTick 校准
- 关键翻转前后**关中断**（`__disable_irq()`），防止时序被中断打乱

### 5. 上拉电阻速查（根据总线长度）

| 场景            | 电阻          |
| ------------- | ----------- |
| 同一PCB，短连线     | 4.7kΩ       |
| 线长>30cm 或多个设备 | 2.2kΩ~3.3kΩ |
| 极低功耗，100kHz以下 | 10kΩ        |
| 绝对不能省         | 无上拉 → 总线不工作 |

### 6. 多从机地址避坑

- 保留地址：`0000 XXX` / `1111 XXX`（不能用 0x00 或 0x7F）
- 同型号从机通过硬件引脚（A0/A1/A2）区分地址
- 调试技巧：发送地址+写位，检测有无 ACK 判断设备是否存在
